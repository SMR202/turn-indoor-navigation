# ADR-0019: Two start hypotheses, compass doubt and lost-position recovery

Date: 2026-11-14
Status: ACCEPTED
Context and evidence: A walk that starts with the heading half a turn wrong could not recover: each hypothesis may correct its heading by at most about 57°, so the dot ran the wrong way until a tap or a code (the FAST report of 2026-11-06 was one form of this). The start heading is often an assumption ("facing along the route") or a compass reading taken near steel. Separately, a cloud in the wrong place stayed there: the signal model tolerates large errors by design (9 dB, heavy tails), so contradicting beacons only nudged it. A large correction, when it came, was drawn as a sprint through corridors.
Decision: (1) The particle filter can start with a second family of hypotheses facing the opposite way: 25% when the heading is assumed from the route, 15% for a compass start, none when the walker marked the direction. Only the leading family is reported (their average is a place nobody is); the lead changes on a clear majority (62%), the route prior acts inside each family so it cannot choose the direction, and a family still in the minority after 25 m is dropped. (2) A `MagneticMonitor` turns magnetometer strength into a disturbance level (deviation from the place's baseline, wobble, values outside Earth's range); while disturbed the filter's heading noise rises up to fourfold, a compass start taken there is widened once, and the venue's compass offset is not learned. (3) Lost position: when some other spot on the floor explains the beacon readings clearly better than every hypothesis for three radio updates in a row (6 nats in total), half the cloud is spread over the floor again and the readings choose; the result is published as `recovered`. (4) Display: a correction longer than 6 m that no step explains is shown as a jump with a "Position updated" note; an uncertainty of 10 m or more draws the dot grey and offers to set the position.
Alternatives considered: A wider heading-correction limit for every hypothesis: lets wall-sliding rotate headings arbitrarily and still cannot cross half a turn quickly. A full-circle start whenever unsure: throws away a usually correct heading. Recovery on rejected updates only: never triggers with the tolerant signal model (tried first; the test showed it).
License/platform implications: `expo-sensors` Magnetometer, already in the builds; feature-detected.
Consequences and risks: In a straight corridor with no beacon and no turn, neither walls nor signals can tell the two directions apart; the told one is shown. Recovery needs three or more beacons heard. All thresholds are PROPOSED.
Validation / revisit trigger: Simulated tests with controls (the old behaviour fails each case): wrong-way starts resolved by beacons and by walls, a lost cloud found again, a correct cloud left alone, disturbance profiles, jump display. EXPERIMENT RESULT (2026-11-14): replaying the 4 recorded assisted home walks that match the current home map, recovery never triggered and the paths were identical with it on and off. Revisit with the first beacon installation and a recorded wrong-way start.
Supersedes / superseded by: Extends ADR-0009 and ADR-0011.
