# ADR-0013: MapLibre as TURN's map engine

Date: 2026-11-06
Status: ACCEPTED
Context and evidence: The visitor map is a custom SVG renderer (`apps/navigator/src/map/VenueMap.tsx`, about 1,600 lines) whose camera runs on Reanimated shared values while the floor plan is SVG paths redrawn by React. Phone testing found layers drifting apart (fixed in October with zero-offset layers), stutter while zooming, missed or wrong taps, no rotation or tilt, and no heading-up follow mode. Users compare the map with Google Maps. Indoor products draw on the GPU: Mappedin (WebGL), Pointr (native maps SDK), MapsIndoors (on Google or Mapbox maps).
Decision: Adopt MapLibre: `@maplibre/maplibre-react-native` 11.x (MIT; new architecture; peer `expo >= 54`, `react-native >= 0.80`; we run Expo 57 and React Native 0.86) on iPhone and Android, and `maplibre-gl` 6.x (BSD-3) on the web (TURN Lite, browser preview, Studio). `@turn/map-scene` turns a venue into one MapLibre style and GeoJSON sources, so every surface draws the same map. Venue metres become longitude/latitude through the venue georeference (ADR-0014); a venue without one uses a neutral origin and its plan orientation. Rooms are fill-extrusions a few centimetres high, walls are polygons extruded to wall height, labels and icons are symbol layers with collision handling, the route and the dot are their own layers. Glyphs (Noto Sans, SIL OFL) and icons ship with the app and the TURN server, so maps work without internet.
Alternatives considered: (1) Keep and optimise the SVG renderer: cannot tilt or extrude cheaply, and its gesture/JS-thread problems are structural. (2) `@shopify/react-native-skia` custom renderer: GPU drawing but we would build camera, gestures, 3D, label collision and web support ourselves. (3) Mapbox: needs an account token and a commercial licence. (4) three.js/WebView: a WebView map on phones adds latency and memory and splits gesture handling.
License/platform implications: MIT and BSD-3, no account or token. Native module: the TURN app needs a new build on both phones. Map tiles are not required (venue data only); an optional outdoor basemap is a separate, licensed choice.
Consequences and risks: The map component is rewritten behind the same props. Glyph and icon assets must be packaged. MapLibre's maximum zoom (about 24) gives centimetre detail, enough indoors. The SVG renderer is kept until the new one is verified on both phones, then removed.
Validation / revisit trigger: Smooth 60 fps pan/zoom/rotate on the iPhone 15 Pro and Pixel 4a 5G; taps select the room or place under the finger; follow mode keeps the dot centred while walking. Revisit if the native module fails on either platform or its new-architecture support regresses.
Supersedes / superseded by: Supersedes the SVG map renderer described in the mobile status (October 2026).
