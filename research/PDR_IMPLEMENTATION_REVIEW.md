IMPLEMENT only TURN's ID resolution, observation adapters, timestamped hysteresis step baseline, measured stride composition, lifecycle guards, replay and test UI. This is a bounded baseline capable of producing evidence, not a claim to outperform mature navigation systems.

## Platform findings

Installed iOS DeviceMotion emits rotationRate alpha=z/beta=y/gamma=x, whereas Android emits alpha=x/beta=y/gamma=z; the baseline does not integrate these inconsistent fields. iOS interval is emitted in seconds while Android emits milliseconds; use native timestamp deltas, not interval. Android repeats some latest sensor values between callbacks; independently deduplicate timestamps. Missing fields/gaps/carry tilt must stop updates rather than invent movement.

## Measurement priority

Heading and step length errors accumulate. At 30m, a constant 10-degree heading error alone creates roughly 5.2m lateral error. QR resets position but does not measure phone direction; explicit heading alignment is required. Calibrate stride from measured distance and counted steps; evaluate on separate walks. Never call the result highly accurate without device/venue evidence. Retain E001–E003 for the deeper evaluation track.
